# 轻进销存 功能简化方案

| 项目 | 内容 |
|---|---|
| 文档日期 | 2026-10-13 |
| 状态 | 已确认，并按 P0–P2 实施完成（2026-10-13）；决策结论见第一节与第十节 |
| 适用范围 | 前端为主，后端只加一个 settings 键和一组示例数据接口 |
| 不涉及 | 数据库表结构变更、已上线数据迁移 |

---

## 一、需求复述

**问题**：LightStock 目前功能相当完整——左侧 11 个菜单，覆盖商品、供应商、客户、多仓库、计量单位、进/出货单据、库存查询、库存流水、报表、系统设置。对**没有接触过进销存/仓库管理系统**的用户来说，一上来就要面对「计量单位换算、多仓库、冲销作废、库存流水台账、自定义字段」这些概念，不知道从哪下手，容易直接放弃。

**目标**：对系统做**信息架构与交互层**的减法，让零基础用户能自己上手跑通「建商品 → 进货 → 查库存」这条主流程。

**已确认的决策**（2026-10-13）：

1. **方式**：简易 / 高级**双模式**，默认极简、高级功能收进开关，**不删代码、不动数据结构**，可随时切回。
2. **简易模式默认隐藏**：`计量单位（换算/重量）`、`自定义字段`。
   **明确保留**：`多仓库`、`库存流水`。
3. **首次使用向导**：要，且**带示例数据**。
4. **菜单归并**：`仓库` 收进「设置 → 仓库」，`库存流水` 并入「库存」页的页签；
   **`供应商` 与 `客户` 保持独立菜单，不合并为「往来单位」**。
5. **老库（已有业务数据）默认「高级模式」**，且不弹向导。

据此，简易模式左侧菜单为 **9 项**（原 11 项）。

---

## 二、目标与非目标

### 目标
- 零基础用户首次打开，**3 分钟内**能独立完成一次「建商品 → 进货 → 查库存」。
- 简易模式下，用户视野里不出现「计量单位」「自定义字段」这两个概念。
- 高级用户一键切回完整功能，**数据零丢失**。

### 非目标（本期不做）
- ❌ 删除任何后端功能或 API（双模式的全部意义就是"隐藏而非删除"）。
- ❌ 修改数据表结构（`settings` 本就是 key/value 表，加键即可）。
- ❌ 移动端 / 桌面端适配。
- ❌ 引入权限体系、多用户体系。

## 三、现状盘点：新用户的难点分布

按代码实际情况盘点，难点集中在四处：

| 位置 | 文件 | 对新手不友好的地方 |
|---|---|---|
| 计量单位 | `web/src/views/Units.vue` | 「换算倍数」「类型(计数/重量)」「每单位重量kg」——需要先理解 1箱=24件 这套换算模型 |
| 商品表单 | `web/src/views/Products.vue:57-66` | 必填「基准单位」+「重量kg/基准」，商品列表还有「折算」「重量kg/基准」两列 |
| 单据明细 | `web/src/views/Orders.vue:77` | 每条明细都要选一次单位 |
| 设置页 | `web/src/views/Settings.vue` | 5 个页签，其中「自定义字段」要填英文字段名、实体、类型 |

另外两处**看起来复杂但其实要保留**的（已被决策确认）：
- `web/src/views/Stock.vue` 的库存流水——出错时对账要用，且已确认保留。
- 多仓库——已确认保留。

> 这里有一个反直觉的判断：**「作废」不能被藏**（`Orders.vue:32`）。新手录错单子是高频事件，作废是他唯一的自救手段，藏掉反而增加求助成本。

## 四、总体方案：简易 / 高级双模式

### 4.1 模式开关

**存储**：复用现有的 `settings` 键值表（`server/src/schema.sql`），新增三个键：

| 键 | 取值 | 用途 |
|---|---|---|
| `ui_mode` | `simple` / `advanced` | 当前界面模式 |
| `onboarded` | `0` / `1` | 是否走完首次向导 |
| `demo_seed_ids` | JSON 数组 | 记录示例数据的商品/仓库 id，供一键清除 |

**接口**：扩展 `server/src/routes/system.js`——`GET /api/settings`（第 10 行）返回值增加 `ui_mode`、`onboarded`、`has_demo`；`PUT /api/settings`（第 17 行）接受 `ui_mode`。**不新增路由**。

**前端**：新增 `web/src/mode.js`，导出一个 `mode` ref 和 `isSimple()` 计算属性；`App.vue:34` 的 `onMounted` 里随 `GET /settings` 一起初始化。所有页面统一从这里取，**不要在 11 个页面里各写一遍判断**——这是控制双模式回归测试面的关键。

**默认值策略**（重要）：

| 库的状态 | 默认模式 | 是否弹向导 |
|---|---|---|
| 全新空库（无商品、无单据） | `simple` | ✅ 弹 |
| 已有数据的库 | `advanced` | ❌ 不弹 |

理由：老用户升级后界面必须和升级前一模一样，否则会被"我的功能不见了"吓到。

### 4.2 菜单映射表（11 项 → 9 项）

在 `web/src/router.js` 给路由加 `meta.simple: false` 标记，`App.vue` 的 `menus` 计算属性据此过滤。

| 现状菜单 | 路由 | 简易模式 | 高级模式 |
|---|---|---|---|
| 仪表盘 | `/dashboard` | ✅ 首页 | ✅ |
| 商品管理 | `/products` | ✅ 商品 | ✅ |
| 供应商 | `/suppliers` | ✅ 供应商 | ✅ |
| 客户 | `/customers` | ✅ 客户 | ✅ |
| 仓库 | `/warehouses` | 收进「设置 → 仓库」 | ✅ 独立菜单 |
| 计量单位 | `/units` | ❌ **隐藏** | ✅ |
| 进货管理 | `/purchase` | ✅ 进货 | ✅ |
| 出货管理 | `/sales` | ✅ 出货 | ✅ |
| 库存查询 | `/stock` | ✅ 库存（页签 1） | ✅ |
| 库存流水 | `/ledger` | ✅ 库存（页签 2） | ✅ 独立菜单 |
| 报表统计 | `/reports` | ✅ 报表 | ✅ |
| 系统设置 | `/settings` | ✅ 设置（少 2 个页签） | ✅ |

> 「仓库」「库存流水」是**换位置而不是隐藏**，路由仍可直达（`meta.simple: false` 只影响菜单显示）。

### 4.3 页面内字段收敛

#### 商品页 `web/src/views/Products.vue`

| 元素 | 位置 | 简易模式 |
|---|---|---|
| 「基准单位」下拉 | 第 57–62 行 | 隐藏，**自动绑定「件」** |
| 「重量kg/基准」 | 第 63 行 | 隐藏，默认 0 |
| 表格列「基准单位」「折算」「重量kg/基准」 | 第 23、31–34 行 | 隐藏 |
| 表格列「平均成本」 | 第 37–39 行 | 隐藏 |
| 「编号」「条码」「规格」 | 第 53–55 行 | 折叠进「更多字段」 |
| 「自定义字段」分隔线 + 组件 | 第 69–70 行 | 隐藏 |

> ⚠️ **必须处理的坑**：`Products.vue:111` 有 `if (!form.base_unit_id) return ElMessage.warning('请选择基准单位')`。简易模式既然隐藏了这个下拉，**就必须在保存前自动填入基准单位 id**（`dimension='count' && is_base=1`，即默认的「件」），否则表单永远存不上。这是最容易漏、且一漏就致命的点。

#### 往来单位 `web/src/views/Partners.vue`
- 「自定义字段」（第 27 行）隐藏；若采纳合并方案，则用页签承载 供应商 / 客户 两个 `kind`。

#### 设置页 `web/src/views/Settings.vue`

| 页签 | 简易模式 |
|---|---|
| 基本设置 | ✅ 保留，**新增「界面模式」开关** + 「清除示例数据」按钮 |

| 数据备份 | ✅ 保留 |

| 扩展路线 | ❌ 隐藏（内容面向开发者，`Settings.vue:98-111`） |

## 五、首次使用向导与示例数据

### 5.1 向导流程

触发条件：`settings.onboarded !== '1'`。新建 `web/src/components/OnboardingWizard.vue`，在 `App.vue` 挂载。

| 步骤 | 内容 |
|---|---|
| 1 | 欢迎 + 选界面模式（默认「简易」） |
| 2 | 填店铺名称 → 写入 `business_name` |
| 3 | 确认仓库（默认「主仓库」，已存在则不重复创建） |
| 4 | 添加 3 个示例商品（矿泉水 / 方便面 / 纸巾，含进价售价），可勾选「暂不添加」 |
| 5 | 引导走一遍进货：跳到进货页并给出操作提示 |
| 6 | 完成 → 写 `onboarded=1`，提示「随时可在设置里切换到高级模式」 |

要点：**每一步都可跳过**，不强制、不阻断，避免用户卡在向导里出不去。

### 5.2 示例数据的一键清除

新增 `server/src/routes/demo.js`，在 `server/src/index.js` 挂载：

- `POST /api/demo/seed`：写入示例商品（`sku` 加 `DEMO-` 前缀便于识别），id 列表记入 `settings.demo_seed_ids`。
- `POST /api/demo/clear`：按记录的 id 删除。**关键**：若商品已被单据引用（`purchase_order_items` / `sales_order_items` / `stock_ledger` 中存在引用），**拒绝删除并明确提示**「该商品已有进出货记录，无法自动清理」，而不是抛外键错误。

前端入口：设置 → 基本设置 底部「清除示例数据」，仅在 `has_demo` 为真时显示。

## 七、分阶段实施计划

| 阶段 | 内容 | 预估 |
|---|---|---|
| **P0** | 模式开关（后端 settings 键 + `mode.js`）+ 菜单过滤 + 设置页开关 | 0.5 天 |
| **P1** | 页面字段收敛（商品 / 单据 / 库存 / 往来单位 / 设置页签）+ 基准单位自动填充 | 0.5 天 |
| **P2** | 首次向导 + 示例数据 seed/clear | 1 天 |
| **P3** | 文案与帮助（术语替换、空状态引导、帮助气泡） | 0.5 天 |

P0 单独上线就有明显效果——菜单立刻少一项、设置页少一个页签，且风险极低。

### P3 的术语建议（低成本、对新手收益大）
| 现状 | 简易模式建议 |
|---|---|
| 库存流水 | 进出记录 |
| 库存调整（盘点/修正） | 库存修正 |
| 进货管理 / 出货管理 | 进货 / 出货 |
| 往来单位（若合并） | 供应商 & 客户 |

## 八、验收标准

1. 全新安装首次打开，**3 分钟内**独立完成「建商品 → 进货 → 查库存」，全程不需要理解「计量单位」和「自定义字段」。
2. 简易模式左侧菜单为 **9 项**，不存在「计量单位」入口。
3. 商品表单隐藏「基准单位」后**仍能成功保存**（自动绑定「件」）——对应 4.3 的坑。
4. 设置里切到「高级模式」后，计量单位、自定义字段、全部页签**立即出现，无需重启**。
5. 从高级切回简易，**数据零丢失**。
6. 示例数据可一键清除；对已产生单据的示例商品给出明确提示而非报错。
7. 已有单据的老库升级后默认高级模式，**界面与升级前完全一致**。

## 九、风险与取舍

| 风险 | 应对 |
|---|---|
| 双模式 = 两条回归测试路径 | 模式判断集中在 `mode.js`，禁止在各页面散落判断 |
| 隐藏必填字段导致存不上 | 简易模式下所有被隐藏的必填字段必须有默认值（基准单位是唯一一处，见 4.3） |
| 老用户以为功能丢了 | 默认高级模式 + 设置页开关常驻 |
| 「简易」被做过头，藏掉了自救手段 | 明确保留「作废」和「库存流水」 |
| 示例数据污染真实账目 | `DEMO-` 前缀 + id 记录 + 有引用时拒绝清除 |

**取舍说明**：这套方案选择「隐藏而非删除」，代价是代码里会长期存在模式分支；收益是任何一步决策做错了都能一键回退，且不触碰数据模型——对个体经营者的生产数据来说，这个取舍是划算的。
